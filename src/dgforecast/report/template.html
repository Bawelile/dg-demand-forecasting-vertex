Project · End-to-end ML engineering · Python · XGBoost · Vertex AI

Store-item demand forecasting, from raw data to a monitored model

A dollar-store chain needs to know how many units of every item each store will sell over the next 14 days. This system builds that forecast every night: it checks the data, builds leak-free features, trains XGBoost, only ships a model that beats the live one, explains every number, and watches itself for drift. It runs on a laptop and compiles to Vertex AI Pipelines.

02 · Data and checks

Realistic demand, validated before use

Two years of daily sales from a simulator built around dollar-store demand: rural and urban stores, SNAP and first-of-month spikes, paycheck Fridays, holidays, promotions with price elasticity, regional storms, new stores, and stockouts. Every run starts by checking the data and stops if a check fails.

03 · Features and training

No peeking at the future

We forecast 14 days ahead, so every sales feature looks back at least 14 days; only planned inputs such as price, promotions, and the calendar describe the target day. Data is split by date, never at random. A unit test changes the most recent 14 days of sales and proves the features don't move.

04 · Evaluation and the gate

Close to the best any model could do

Scored on 28 days the model never saw, against a seasonal-naive baseline ("same weekday two weeks ago"). Because the simulator knows true expected demand, we can also score a perfect forecast: the error left over is day-to-day randomness no model can predict.

07 · Registry, pipelines, tests

Built to run without a babysitter

Approved models are versioned with a model card; one version is the live champion. The same steps compile into two Vertex AI pipelines: weekly training with the gate as a conditional branch, and daily monitoring that can trigger retraining. CI runs the tests and compiles the pipelines on every push.
